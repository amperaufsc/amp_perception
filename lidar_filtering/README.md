# lidar_filtering 
This package is responsible for processing and manipulating the point cloud generated by the LiDAR. It contains a file (```lidar_fusion.cpp```) that performs the fusion between the camera image and the LiDAR point cloud. In addition, it filters the points that lie inside the bounding boxes of the cones detected by the camera and then clusters the selected points into a Track message, which consists of a list of cones with three-dimensional coordinates.

The other file (```fusion_image.cpp```) performs only the fusion between the camera image and the raw LiDAR point cloud, and is intended solely for debugging and validation of the fusion correctness.

## The lidar_filtering package is designed to:
→ Acquire camera calibration data (intrinsic and extrinsic parameters)  
→ Acquire Inference data (Or image data for debugging) and Pointcloud from LiDAR  
→ For each incoming LiDAR point cloud, apply camera–LiDAR data fusion  
→ Filter points projected inside the detected bounding boxes  
→ Cluster the filtered points to generate individual Cone objects  
→ Aggregate all clustered Cones into a Track object  
→ Publish ROS 2 topics in standard reference frames  
→ Provide spatial information suitable for further processing

# Dependencies

Core dependencies (minimum):

- ROS 2 Humble (or newer)
- `rclcpp` / `rclpy`
- `yolov8_msgs`, `geometry_msgs`, `sensor_msgs`, `lifecycle_msgs`, `fs_msgs`, `opencv`, `pcl`
- `tf2` + `tf2_ros`
- `colcon` (build system)

---

## Runtime Requirements / Prerequisites

Before running the `lidar_filtering` package, the following components **must be running**:

### Camera (DepthAI)
The camera must be launched using the DepthAI ROS 2 driver:
```bash
ros2 launch depthai_ros_driver camera.launch.py
```

### Neural Network Inference (YOLOv8)

The object detection pipeline must be running to provide inference results:
```bash
ros2 launch yolobot_recognition launch_yolov8.launch.py
```

### LiDAR (Ouster)

The LiDAR sensor must be launched using the Ouster ROS 2 driver:
```bash
ros2 launch ouster_ros sensor.launch.xml \
  sensor_hostname:=<sensor_host_name>
```

> These nodes provide the required camera images, inference data, and LiDAR point clouds consumed by the lidar_filtering package.
